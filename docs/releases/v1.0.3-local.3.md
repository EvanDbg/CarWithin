# CarWithin Local v1.0.3-local.3

应用版本：1.0.3 / build 18。实验性预发布，补齐会话公钥并增强连接诊断。

## 本次针对的问题

build 17 的真机日志中，直接回环和 LocalDevVPN 两种模式的监听器均已就绪，iOS 已接受 MFi 配件认证及识别，但发送 CarPlay StartSession 后未观察到就绪的控制连接。排查发现 `0x4301` 请求中的 AirPlay 公钥字段仍为空。

## 修改

- 将接收器实际用于 Pair-Setup/Pair-Verify 的 Ed25519 公钥写入 StartSession。公钥由监听器就绪回调连同实际端口传递，不另生成一把密钥，不使用 MFi 证书公钥替代。
- 本机模式要求 32 字节公钥，线上字段为 64 个小写十六进制字符和 NUL 结束符；在建立虚拟配件前检查请求，同次启动的重试复用同一份编码。
- 保持远端 iPad 的原 Wi-Fi 兼容路径，不把发送手机的身份当作远端接收器身份。
- 记录入站控制连接及其等待、失败、取消和就绪状态；记录启动前配置检查、设置保存等拒绝原因，避免只有“画面计划”却看不到退出原因。
- 隔离旧会话的就绪、控制连接和失败回调，避免它们干扰新的启动或停止操作。
- 将 `0x4300` 的 wired/wireless 可用性与 ACC 端点传输类型分开描述，明确“已发送 StartSession”还不代表 iOS 已接受会话。

## 安装和复测

下载 `CarWithin-Local-unsigned.ipa`，沿用自己的签名方式安装。确认“设置 → 关于”显示 build 18。如果原来的配件身份仍显示已载入并通过自检，无需重新生成或导入那三个身份文件。

优先选择“仅本机（无需 VPN）”，开启蜂窝、关闭测试 VPN，在系统设置中明确记录 Wi-Fi 是未关联还是完全关闭。只点一次启动，留在前台等待自动结果：没有就绪控制连接时约 45 秒会停止；若控制连接已建立但没有视频样本，总启动期限为 75 秒。

反馈请附从“启动请求”到最终结果的完整日志，以及 iOS 完整版本、Wi-Fi 状态和 App build。观察是否新增“控制入站”、连接失败原因，或 `/pair-setup`、`/pair-verify`、媒体和首帧日志。只通过配件认证或只收到 TCP 都不算完整成功。

## 验证与边界

发布检查包括协议编码和无效公钥回归测试、本机 socket 实测及完整 iOS Release 无签名构建，结果见本次 GitHub Actions。CI 不执行 iPhone 私有 CarPlay 握手或屏幕验收。

本版本保持原有地址、ACC transport type、Wi-Fi 凭据省略和关闭对外共享的策略，先排除公钥缺项。仅 wired 属性配 IPv4 地址是否满足当前 iOS 的接口/发现条件仍未证实，因此不能承诺升级后必定出画。LocalDevVPN 维护者也报告过[纯蜂窝限制](https://github.com/jkcoxson/LocalDevVPN/issues/31)，不能仅凭 App 自己的回送测试宣称系统 CarPlay 已能走该路径。

公共 IPA 不包含 MFi 配件身份、证书私钥或 Apple 签名材料。
